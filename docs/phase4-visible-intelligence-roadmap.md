# Phase 4：可感知的智能学习产品升级

## 0. 目标

Phase 1–3 主要解决契约可靠性、确认门禁、响应式布局和设计系统，价值重要但不够直观。Phase 4 改为以用户可见结果验收：

1. 用户知道 AI 用了哪个策略、何时切换模型、为什么要求确认。
2. 几何、方程、证明等题目呈现不同的专业分析结构。
3. 用户能在原卷上直观看到、调整、合并和拆分题目区域。
4. 首页能回答“本周哪里进步、哪里反复错、下一步做什么”。
5. 任意题目或报告可在 3 步内预览、脱敏、导出或分享。
6. 高级用户能配置模型；普通用户只需选择“准确/均衡/省钱/隐私”策略。

## 1. 现状审计

### 已有但不直观

- 已有 PaddleOCR、MinerU、Vision、自定义版面服务以及 Paddle → MinerU 自动升级，但质量判断主要依赖候选数、覆盖率和重叠率。
- 已有题目切分、区域确认、OCR/用户修正/AI 规范化三层信息，但 block 缺少统一的坐标、层级、阅读顺序和来源审计模型。
- 已有周报聚合、HTML/PDF 分享，指标包括新增题、复习次数、掌握率、错因、薄弱知识点和连续天数，但入口偏深、以静态报告为主，缺乏环比和下一步行动。
- 已有 HTML/PDF/Markdown/JSON/CSV/Anki 等导出能力，但入口和选项分散，缺少统一的“分享作品”体验。
- AI Provider 当前是单个 `AiProviderConfig`，服务、模型、密钥、超时混在一张表单中；没有 provider 列表、任务路由、降级链和费用/健康状态。
- `QuestionType` 只有通用题型。几何、方程组属于解题领域/分析画像，不宜继续硬塞进通用题型枚举。

## 2. 总体架构

处理链调整为：

`页面理解 → 题目区域确认 → 题目画像分类 → 专用解析 → 模型策略执行 → 字段级裁决 → 人工确认 → 学习事件 → 报告/导出`

新增三个核心层：

- `TaskProfile`：描述任务是什么，如版面检测、普通分析、几何分析、证明校验、练习生成。
- `ModelStrategy`：描述该任务用什么模型、何时重试/降级/复核。
- `LearningEvent`：描述用户从识别、修正、复习到掌握的变化，支撑可信趋势。

## 3. 多模型对比与兜底策略

### 3.1 用户可见设计

分析页顶部显示“AI 执行轨迹”，而不是后台静默切换：

- `主模型分析完成 · 4.2 秒`
- `答案置信度偏低，已调用复核模型`
- `两模型在第 3 步存在分歧，请确认`
- 点击后查看字段级对比，不直接展示两大段难读的完整答案。

字段对比卡：

| 字段 | 主模型 | 复核模型 | 系统结论 |
|---|---|---|---|
| 最终答案 | x=2 | x=2 | 一致 |
| 第 3 步 | 除以 x-1 | 先讨论 x=1 | 有风险，需确认 |

提供“只在有风险时复核”和“本题立即双模型对比”，默认不让用户承担双倍成本。

### 3.2 路由规则

默认策略不是“每题调用两个模型”，而是风险触发：

1. 主模型请求失败、超时、限流：按降级链切换。
2. JSON/契约校验失败：同模型修复一次，仍失败则切换。
3. 字段低置信、证据不足、答案与步骤矛盾：调用复核模型，仅复核风险字段。
4. 几何图、复杂表格、手写密集：路由到视觉能力更强的模型。
5. 高风险证明题：执行“生成 + 独立审查”，不允许审查模型覆盖原证据。

### 3.3 数据模型

- `AiProviderProfile`：服务商、URL、密钥引用、可用模型、健康状态。
- `AiModelProfile`：modelId、视觉/JSON/上下文能力、价格级别、延迟等级。
- `ModelStrategy`：名称、模式、任务路由、预算、隐私规则。
- `TaskRoute`：taskProfile、primaryModel、fallbackChain、reviewModel、触发条件。
- `ModelRun`：requestId、模型、耗时、状态、token/费用估算、失败类型、输出 fingerprint。
- `FieldCandidate`：字段值、置信度、证据、来源 runId。
- `ArbitrationResult`：一致/冲突/采用来源/需人工确认及理由。

禁止保存 API Key 到运行记录；原始响应继续遵循现有显式开启和保留期策略。

### 3.4 验收

- 模拟主模型超时后，用户能看到已降级且结果可继续完成。
- 低风险普通题只请求一次；低置信字段才触发局部复核。
- 用户能查看字段级分歧和采用理由。
- 每次切换都有可审计原因，不能静默覆盖。

## 4. 题目类型专用解析器

### 4.1 不扩张 `QuestionType`，新增 `AnalysisProfile`

`QuestionType` 继续表示作答形式：选择、填空、计算、证明等。新增分析画像表示解题领域：

- `generic`
- `algebraEquation`
- `equationSystem`
- `geometry`
- `functionGraph`
- `proofArgument`
- `physicsCalculation`
- `chemistryExperiment`
- `languageReading`

画像可由规则 + AI 分类，低置信时允许用户在确认页一键改。

### 4.2 专用结构与界面

#### 几何

结果页显示：

- 已知条件
- 求证/求解目标
- 图形对象：点、线、圆、角
- 关系：平行、垂直、相切、全等、相似
- 解题步骤，每步附定理依据
- 图文一致性风险，例如“题干提到点 D，但图形区域未识别到”

首版不做完整自动作图，先做到“结构化对象 + 原图高亮 + 定理链”。

#### 方程/方程组

- 未知量与定义域
- 方程/约束列表
- 等价变形步骤
- 解集
- 代回验证
- 增根、漏解、除零风险

首版加入确定性校验：最终解代回原式；分母非零和根号定义域检查。不要一开始引入庞大 CAS。

#### 证明题

- 命题、前提、结论
- 证明步骤
- 每步依据
- 依赖关系图
- 跳步/循环论证/未使用条件

生成模型负责提出证明，审查模型或规则负责找缺口；二者角色必须分离。

### 4.3 Parser 接口

- `QuestionProfileClassifier`
- `SpecializedAnalysisParser<T>`
- `SpecializedResultValidator<T>`
- `SpecializedResultRenderer<T>`

Prompt 与 schema 按画像独立版本化，公共字段仍兼容 Contract V2。专用结果以扩展 payload 持久化，避免破坏旧题。

### 4.4 验收

- 三种样例题进入结果页时，用户不看说明也能一眼分辨是三套不同工作台。
- 方程结果能显示代回验证。
- 证明题能标出至少一种“缺依据/跳步”风险。
- 用户改画像后可仅重跑专用字段，不重新 OCR。

## 5. 更强的题目切分与版面理解

### 5.1 数据结构升级

把当前 `DocumentBlock(type, content)` 升级为页面图模型：

- `DocumentPage`：页码、尺寸、方向、原图。
- `LayoutBlock`：id、bbox、polygon、type、text、confidence、source、readingOrder。
- `BlockRelation`：belongsTo、continuesOnNextPage、captionOf、optionOf、diagramOf。
- `QuestionGroup`：题号、题干、选项、作答、图形、子问、跨页关系。

原始 block 永远保留；用户操作生成 correction，不破坏来源。

### 5.2 多引擎融合

不再只看“候选框数量/覆盖率/重叠率”，增加：

- 题号连续性与重复题号
- 选项是否被拆散
- 题干与作答区距离
- 图形/表格是否归属明确
- 阅读顺序是否跨栏跳跃
- 页尾未完句与下一页续题
- OCR 文本完整度、公式完整度

Paddle 快速检测；质量评分不达标时升级 MinerU/视觉模型；只对问题区域升级，避免整页重复成本。

### 5.3 用户可见交互

“试卷地图”作为确认页核心：

- 原图覆盖彩色题框，题号直接贴在框上。
- 点框后右侧/底部展示题干、选项、作答、图形块。
- 拖边调整；长按框可合并；在框内划线可拆分。
- 跨页题显示链条标识 `第 3 题 → 下一页续题`。
- 风险角标：`选项可能漏识别`、`图形归属不确定`。
- 提供“一键接受高置信区域”，只让用户处理红黄风险。

### 5.4 验收

- 双栏、带图、带表格、多小问、跨页各有固定 fixture 回归。
- 用户可在不进入文本编辑器的情况下完成合并/拆分/重排。
- 低风险区域批量确认，高风险区域不得静默进入分析。

## 6. 学习档案、周报与成长反馈

### 6.1 从“统计页”改成“学习故事”

现有周报只展示绝对数量。新首页首屏增加“本周成长”卡：

- `方程组正确率 58% → 76%`
- `粗心计算连续出现 3 次`
- `几何证明仍需加强：依据缺失 4 次`
- 主行动按钮：`做 5 道针对练习`

点开进入学习档案：

1. 趋势：正确率、掌握度、复习完成率及上周环比。
2. 能力图谱：学科 → 知识点 → 错因，可追溯到原题。
3. 成长事件：首次掌握、连续复习、某错因下降。
4. 下周计划：系统建议 + 用户可编辑目标。

### 6.2 数据可信性

新增事件流而不是从当前状态反推历史：

- `questionCaptured`
- `recognitionCorrected`
- `analysisConfirmed`
- `exerciseAttempted`
- `reviewCompleted`
- `masteryChanged`
- `goalCompleted`

生成 `DailyLearningSnapshot` / `WeeklyLearningSnapshot`，冻结当周基线。所有数值由确定性聚合产生；AI 只负责把指标写成自然语言，不允许编造数字。

### 6.3 反馈原则

- 不只说“错了几题”，必须说明“变化 + 原因 + 下一步”。
- 无足够样本时显示“数据不足”，不生成虚假趋势。
- 每条洞察可点击查看证据题目。
- 家长版与学生版语气、字段不同，但使用同一可信数据。

### 6.4 验收

- 首页首屏可看到一条变化、一条风险和一个行动。
- 每个趋势数字能下钻到题目/复习日志。
- 周报支持本周与上周对比；空数据有合理状态。

## 7. 导出与分享

### 7.1 统一“分享作品”工作台

将现有分散导出能力统一成三步：

1. **选内容**：当前题、所选题、某知识点、本周报告、专项练习。
2. **选用途**：自己复习、发老师、发家长、打印练习、迁移数据。
3. **预览并分享**：模板、答案显隐、隐私脱敏、格式。

用途自动推荐默认格式：

- 老师：PDF/图片，带学生答案与错因。
- 家长：成长周报 PDF，隐藏 API/模型诊断信息。
- 自己复习：Anki/Markdown。
- 数据迁移：JSON/CSV。

### 7.2 关键体验

- 题目详情、错题列表、学习档案都提供统一分享入口。
- 分享前必须有真实预览，不先弹复杂参数表。
- 默认隐藏姓名、原始照片元数据和模型诊断；用户显式开启才带出。
- 保存导出配方，例如“每周日家长版周报”。iOS 定时触发需依赖 Shortcuts，应用内只提供快捷动作/URL scheme。
- 导出历史显示来源范围、模板、格式、时间，可重新生成；不要把临时文件当唯一历史记录。

### 7.3 验收

- 从题目详情到系统分享面板不超过 3 步。
- PDF/图片/Anki/JSON 至少各有一条端到端测试。
- 任何公开分享默认通过隐私扫描。

## 8. 真正的模型策略配置中心

### 8.1 信息架构

设置页拆成两层：

#### 普通模式：策略卡

- **均衡（默认）**：普通题单模型，风险字段自动复核。
- **准确优先**：复杂题双模型审查，允许更高成本。
- **省钱优先**：轻量模型为主，仅失败时降级。
- **隐私优先**：只使用被标记为本地/私有部署的服务。

每张卡显示“预计速度、费用、准确性、隐私”，不暴露 URL 等技术细节。

#### 高级模式：提供商与任务路由

- 提供商列表：连接状态、模型数、最近成功、延迟、限流状态。
- 模型列表：能力标签（视觉/结构化/长上下文）、费用级别。
- 任务路由矩阵：版面理解、普通分析、复杂题、复核、练习生成、周报文案。
- 降级链可拖拽排序。
- 测试中心使用内置小 fixture 分别测试文本、视觉和结构化输出，不再只测“接口能连通”。

### 8.2 与安全/运行态结合

- Provider 与 Strategy 分离：修改策略不复制密钥。
- 保存前检查循环降级链、缺失视觉能力、隐私策略冲突。
- 展示最近 7 天成功率/P50 延迟/降级次数/估算费用；本地无价格表时明确标“仅估算”。
- 分析执行页可临时覆盖“本题使用准确优先”，不修改全局默认。

### 8.3 验收

- 新用户只选一个策略即可工作。
- 高级用户能配置两个 provider、多个模型和每任务路由。
- 删除主模型前会提示受影响策略，不能留下断链。
- 策略模拟器可说明一个示例题将走哪条链以及原因。

## 9. 实施顺序：每个里程碑都必须直观

### Phase 4A：智能策略与可见执行轨迹

先做 Provider 列表、策略卡、任务路由、降级执行器、分析页执行轨迹。它是后续专用解析和版面融合的基础。

交付后用户直观看到：模型选择不再是一张 URL 表单；分析失败会自动恢复，并明确说明原因。

### Phase 4B：三类专用解析 MVP

实现方程/方程组、几何、证明三种画像、schema、验证器和专用结果卡。先用 fixture 建回归，不追求覆盖所有学科。

交付后用户直观看到：不同题型不再共用同一套泛化答案模板。

### Phase 4C：试卷地图与版面图

先迁移统一 block 数据模型，再做框选、合并、拆分、跨页、局部升级和风险门禁。

交付后用户直观看到：原卷上直接整理题目，不再靠猜 OCR 文本属于哪题。

### Phase 4D：学习档案 2.0

补事件流与历史快照，重做首页成长卡、档案页和可下钻周报。

交付后用户直观看到：打开 App 第一屏就知道本周进步和今天该做什么。

### Phase 4E：统一分享作品

复用现有导出引擎，先重做入口、用途模板、预览、脱敏和导出历史，不重复造 PDF/HTML 基础设施。

交付后用户直观看到：任意题目/周报三步可分享，输出更像成品而不是数据文件。

## 10. 不建议的路径

- 不同时开六条线，会造成模型、数据和 UI 三次返工。
- 不默认每题双模型，成本和等待时间不可控。
- 不把几何/方程组直接塞进 `QuestionType`，作答形式与解题领域是两个维度。
- 不先做完整 CAS、自动几何推理或“万能 agent”；首版先做结构化、风险发现和确定性校验。
- 不让 AI 生成不可追溯的成长数字。
- 不重写已有导出引擎，重点应是统一入口、预览、用途和隐私。

## 11. 推荐首个开发切片

首个可合并切片控制在以下范围：

1. 新增 `AiProviderProfile`、`AiModelProfile`、`ModelStrategy`、`TaskRoute` 数据模型与兼容迁移。
2. 把当前单 Provider 自动迁移成“默认提供商 + 均衡策略”。
3. 新增策略中心首页（4 张策略卡）和高级提供商列表。
4. 在分析请求外包一层 `AiTaskRouter`，先支持主模型失败/超时后的单级 fallback。
5. 分析结果页显示执行轨迹和降级原因。
6. fixture 覆盖成功、超时、限流、契约失败、fallback 成功、全链失败。

这个切片完成后即可发 IPA 实机验收，视觉和行为都能被直接感知，再进入字段级双模型复核。
